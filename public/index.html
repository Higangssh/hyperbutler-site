Docker on Windows.
Less RAM. Less disk. No WSL.

hyperbutler is a lightweight, Docker‑compatible engine. It boots a minimal Linux VM through the Windows Host Compute Service, runs dockerd inside it, and lets the stock docker CLI talk to it.

Download for Windows GitHub

Windows 11 Home, Pro, Enterprise · x64 · MSI or zip · Apache-2.0

Features

Works well by default.

No tuning, no extra subsystem to keep updated. Install it, start it, run containers.

  • No WSL

    The VM runs directly on the Windows Host Compute Service, the same API WSL 2 uses. WSL is not required, can stay disabled, and its updates do not affect hyperbutler.

    3 resident processes at idle

  • Works on Windows 11 Home

    Home is first-class; Pro and Enterprise work too. You need an x64 PC with virtualization enabled in the firmware.

  • Disk space given back automatically

    Delete images and the data disk shrinks on its own. No manual compaction, no admin step.

  • Fast bind mounts from C:\

    Mount a Windows folder with -v C:\src:/src. Reading 2000 small files took 0.4 s.

  • Stock docker CLI + Compose

    The docker CLI and the compose plugin are bundled and set up through a hyperbutler docker context. Compose builds, healthchecks, service names, volumes and bind mounts are tested.

  • No telemetry

    hyperbutler sends no usage data. The app only checks GitHub for updates once a day, and you can turn that off.

  • Open source, Apache-2.0

    The source is on GitHub. Free to use at any company size.

How it works

Three small parts, no WSL in between.

Your tools talk to a process of your own, which talks to a small Linux VM over Hyper‑V sockets. A tiny Windows service is the only privileged part: it starts and stops that VM, and nothing else.

Your tools

docker CLI · Compose · SDKs

Unchanged. They use a hyperbutler docker context.

named pipe

Runs as you, no admin

hyperbutler engine

  • Docker API relay
  • User-mode network: NAT, DNS, published ports
  • Fast file server for bind mounts from C:\
  • Disk-space guard, status, the window
Hyper‑V sockets

Linux VM on HCS

dockerd + containerd

  • Minimal Alpine, read-only system disk pinned by hash
  • Data disk gives freed space back to Windows
  • Answers only your engine, with a per-VM secret

Windows service from v0.1.0

hyperbutler broker

The only part that calls the Host Compute Service. Seven short, typed requests (start, stop, status…) over a pipe only you can open, a fixed VM template, and no paths or command lines from the caller. So you need neither admin rights nor the Hyper‑V Administrators group.

Install

Three steps to hello-world.

You need Windows 11 (Home, Pro or Enterprise) on x64, with virtualization enabled in the firmware.

  1. 1

    Run the MSI

    Download it from the latest release. One UAC prompt, then it:

    • adds hyperbutler and its docker CLI to the PATH;
    • adds you to Hyper-V Administrators, if you leave that box ticked;
    • turns on Virtual Machine Platform if it is missing.
  2. 2

    Sign out and back in

    The group membership applies at your next sign-in. If Virtual Machine Platform was just turned on, Windows asks for a restart instead.

  3. 3

    Run a container

    > hyperbutler start
> docker run hello-world

Unsigned preview

Builds are not code-signed yet, so SmartScreen says “Windows protected your PC”: choose More info, then Run anyway. Check the file against SHA256SUMS from the release first: 

Get-FileHash .\hyperbutler-*-windows-amd64.msi -Algorithm SHA256

About Hyper-V Administrators

The group lets every program you run control the Hyper-V VMs on this PC, not just hyperbutler. Treat it as close to admin rights. Prefer no installer? The zip needs no admin rights for itself; see the install guide.

Preview

This is an early preview.

It works end to end on Windows 11 Home, but some things are still open. Among them:

  • The 24-hour soak test has not been run (the 1-hour run passed).
  • Until the HCS access broker ships, your account needs Hyper-V Administrators membership.
  • Docker Compose has not been tested yet.
  • Bind mounts from Windows paths work, but are not yet fast for write-heavy trees: use a named volume for node_modules.
  • Builds are not code-signed, and the installer is English only.
